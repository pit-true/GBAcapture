# GBA (AGB-001 初期型) 40ピン LCD コネクタ「P2」ピン配置 — 検証済み

出典: 任天堂サービスマニュアル回路図（P2 - LCD CONNECTOR 40pin）の
スキャンを収録した https://github.com/squk/GBA-LCD 。
独立実装 https://github.com/zwenergy/gbaHD （40ピンGBA対応コンソライザ）の
配線表・制約ファイルと **17信号すべて一致** することを確認済み（2026-07-05 調査）。

## ピン配置表

| ピン | 信号 | 機能 |
|---|---|---|
| 1 | TST2 | テスト（実質NC） |
| 2 | TST1 | VSHD に接続 |
| **3** | **DCLK (DCK)** | **ドットクロック**（負エッジ有効、可視区間のみ240パルス/ライン、4.19MHzバースト） |
| **4** | **LP** | **ラインラッチ**（正エッジ、~13.6kHz、常時動作） |
| 5 | PS | パワーセーブ（表示中H、VBLANKでデューティ低下 → 「定常H+60Hzブリップ」に見える線） |
| 6 | **DGND** | デジタルGND ← **GND基準はここ推奨** |
| 7 | VSHD | ロジック電源 |
| **8–12** | **LDR5…LDR1** | **赤 bit4…bit0**（⚠️ ピン8がMSB、ピン12がLSB） |
| **13–17** | **LDG5…LDG1** | **緑 bit4…bit0**（同上） |
| 18 | G0 | 「緑bit-1」名目だが **GNDに直結**（向き判定の目印に使える） |
| **19–23** | **LDB5…LDB1** | **青 bit4…bit0**（同上） |
| 24 | SPL | ソースドライバ開始（DCLK動作中のみ） |
| 25 | CLS | ゲートドライバクロック（ライン周期で常時） |
| **26** | **SPS** | **フレーム開始/VSYNC**（59.737Hz、負パルス = ほぼHで1フレームに1回落ちる） |
| 27 | TST3 | VSHD に接続 |
| 28 | MOD | ゲートドライバAC制御 |
| 29 | VCOM | LCDコモン駆動（ライン周期AC） |
| 30–33 | VEE/VSS/VCC/VDD | パネル電源系 |
| 34 | VSHA | アナログ電源 |
| 35 | AGND | アナログGND |
| 36–40 | V4…V0 | LCDバイアス波形（~6.8kHz、2.3–3.7Vpp。40ピン機のみ存在） |

（40ピンのピン2–26 = 32ピン版のピン1–25を+1シフトしたもの）

## ⚠️ ピン1の向きの判定方法（テスタの導通チェックだけでできる）

文献にはコネクタの左右どちらがピン1かの確実な記載がない。**GNDピンの並びで判定する**:

- 正しい向きで見たとき、GNDに導通するのは **端から6番目(DGND) と 18番目(G0)**
- 逆向き（ミラー）に数えていた場合、GND導通は「6番目と **23番目**」に見える

→ 片端から数えて **18番目と23番目のどちらがGNDに落ちているか**で向きが一意に決まる。
（GND基準はカートリッジスロットのシールドや電池端子マイナスでよい）

## 2026-07-05 の診断結果との整合

現状の全タップが「定常HIGH駆動＋~60Hzブリップ、映像活動なし」だった件は、
**ピン番号を逆順（n → 41−n）に数えて配線した**と仮定するとよく説明できる:
ミラーだと DCLK(3)→V2バイアス、RGB(8–23)→MOD/VCOM/電源領域に乗る。

## 正しいタップ位置（nano側の割り当ては現状維持）

| nano側 | 信号 | → GBA P2 ピン |
|---|---|---|
| G | GND | **6 (DGND)** |
| PA0 | DCK | **3** |
| PA1 | LP | **4** |
| PA2 | SPS | **26** |
| PC4 | LDR1 | **12** |
| PC5 | LDR2 | **11** |
| PB0 | LDR3 | **10** |
| PB1 | LDR4 | **9** |
| PB10 | LDR5 | **8** |
| PB11 | LDG1 | **17** |
| PB12 | LDG2 | **16** |
| PB13 | LDG3 | **15** |
| PB14 | LDG4 | **14** |
| PB15 | LDG5 | **13** |
| PB9 | LDB1 | **23** |
| PB8 | LDB2 | **22** |
| PB5 | LDB3 | **21** |
| PB4 | LDB4 | **20** |
| PB3 | LDB5 | **19** |

- LDx1=最下位ビット(LSB)として割り当てている（各色ブロック内で**大きいピン番号ほど下位ビット**）。
  万一逆でも階調が変になるだけなのでソフトで直せる
- 参考: gbaHD はFFCピンでなく**基板表面上部のテストポイント**（TP22=DCLK等）に
  ハンダ付けしている。32ピン基板の図だが40ピン基板にも類似配置の可能性があり、
  パターン剥がれが心配なら TP パッドの利用を検討する価値あり
  （https://github.com/zwenergy/gbaHD の figures/displaypins.png）

## 配線後の検証手順（ソフトは準備済み）

```bash
cd host
dotnet run --project GbaCap.Cli -- rawdiag   # DCK/LP/SPSにエッジ多数・RGBが活発なら成功
dotnet run --project GbaCap.Cli -- freq      # DCK≈2.29M/s, LP≈13618/s, SPS≈60/s が期待値
dotnet run --project GbaCap.Cli -- capture gba.bmp   # 一発目の映像取得！
```
