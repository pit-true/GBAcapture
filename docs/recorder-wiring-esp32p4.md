# ESP32-P4-Pico レコーダ 配線と使い方

`docs/recorder-plan-esp32p4.md`（設計・リスク・ケース計画）の実作業版。
**はんだ・結線はここ通りにする。番号でなく基板シルクの名前で書く。**

対象: Waveshare ESP32-P4-Pico（ESP-IDF v5.5.5、`recorder/`）。
nanoCH32V305 側（FW v0.33・GBA への 19 本タップ）は**変更しない**。

---

## 1. ボタン（録画開始/停止の 1 個だけ）

| もの | 接続 |
|---|---|
| タクトスイッチ **TS-06104**（6x6 表面実装） | **GPIO2 ↔ GND** |

- **外付け部品は不要。** GPIO2 は内部プルアップ有効で読む（`recorder/main/board.c`）。
  プルアップ抵抗もコンデンサも付けない。
- デバウンスはソフトウェア。**5ms 周期で読み、30ms 連続で同じ値なら確定**とする
  （`recorder/main/button.c`）。チャタリングは無視されるので、カチャカチャ押しても 1 回扱い。
- 押した瞬間（Low になった縁）で 1 回イベント。長押しは 1 回。
- GPIO2 はストラッピングピンではない（P4 のストラップは GPIO34〜38）ので、
  ボタンで PullDown したまま給電しても起動は壊れない。
- TS-06104 は SMD なので、**SMD→2.54mm 変換基板か小片ユニバーサル基板に載せて
  リード線 2 本を出す**。ケースの壁にスイッチを固定し、2 本をヘッダへ。

### ヘッダ上の場所（40 ピンヘッダ）

40 ピンは 20 本 x 2 列。**片側の列に `GND`・`GPIO3`・`GPIO2` が 3 本連続で並んでいる**
（列の並び順に `… GPIO4, GND, GPIO3, GPIO2, SCL …`）。

- ボタン = **`GPIO2`** と、その 2 本隣の **`GND`**
- 録画 LED = 隣同士の **`GPIO3`**

基板シルクの GPIO 番号で確認すること。パッド番号（1〜40）は資料によって
食い違いがある（下記 6 節）ので**パッド番号では結線しない**。

## 2. LED

| LED | 接続 | 挙動 |
|---|---|---|
| 録画 LED（赤 3mm 推奨） | **GPIO3 → 470Ω → LED → GND** | 録画中に点灯。SD が無い/読み込めないときは 4 回点滅 |
| 電源 LED（緑 3mm） | **`3V3` → 1kΩ → LED → GND** | 給電されていれば点灯 |

- 極性: GPIO 側がアノード（+）、GND 側がカソード（−）。
- 基板載せ替えのとき GPIO3 はボタンと隣なので、LED の 2 本を隣の 2 ピンに差すと配線が短い。

---

## 3. nanoCH32V305 への接続（映像・音声の受信）

ケース壁に出る **MX1.25 4 ピン**のケーブル 1 本。基板の **4 ピン USB ヘッダ（P1）** から
ESP32-P4 の専用 HS PHY（GPIO49/50）へ直接出ている。

| P1（MX1.25 4P） | 色 | Type-C オス変換基板側 |
|---|---|---|
| V | VCC_5V | VBUS |
| D- | USBD_N | D- |
| D+ | USBD_P | D+ |
| G | GND | GND |

- **CC の処理は不要**（nano 側は 5V 直結の受電デバイス）。
- D+/D- は **15cm 以内・2 本を撚る**。
- **手持ちの 1.25mm 6P ケーブルは 4P ヘッダに入らない。4P が必要**（2026-07-08 確認）。
- 基板の Type-C ソケット（CH343P 経由）は **書き込み・ログ・給電専用で、USB データは通らない**。
  nano をここに挿しても映像は来ない。

---

## 4. 電源

モバイルバッテリー（Type-C）から給電する。

- 基板自身の Type-C から給電するのが最も簡単（書き込みケーブルと同じ穴）。
- ケース面に電源用 Type-C を増設する場合（plan 75 行目）:
  **`VBUS` シルクのピン** → **SS14（ショットキーバリア）** → **`VSYS` シルクのピン**。
  GND は GND へ。D+/D- は MSC 用に **`GPIO27`=D+ / `GPIO26`=D-**（未実装機能）。
  パネル Type-C の **CC1/CC2 に 5.1kΩ プルダウン必須**（C-C ケーブルに 5V を出させるため）。
- ショットキーを入れるのは、基板 Type-C と同時挿しで 5V 同士がぶつかるのを防ぐため。

---

## 5. microSD

- 基板の TF スロット（SDIO 4bit: CLK=43 CMD=44 D0=39 D1=40 D2=41 D3=42）。**配線不要。**
- **FAT32 でフォーマット**して挿す（32GB 以下が手軽。exFAT は使わない）。
- 給電スイッチ Q1(SI2301) のゲート GPIO は回路図で未確認。既定は常時給電扱い
  （`CONFIG_GBAC_SD_PWR_GPIO=-1`）。実機で判明したら Kconfig に番号を書く。

---

## 6. パッド番号についての注意（要実機確認）

設計書 `recorder-plan-esp32p4.md` は Pico 互換ピンを `VBUS(40) / VSYS(39) / 3V3(36)` と
書いたが、コミュニティの KiCad シンボルでは **VBUS=21 / VSYS=22 / 3V3=25** で、
番号が食い違っている。**シルクの名前で判断する**こと。実機でシルクを写メして
この表を確定させたら、ここに「実測 2026-xx-xx」と書く。

## 7. 使い方

### 録画
1. microSD を挿し、モバイルバッテリーで給電する（電源 LED 点灯）。
2. nano のケーブルを繋ぎ、GBA の電源を入れる。
3. **ボタンを 1 回** → 録画 LED 点灯、`/sd/REC_0001.mp4` に記録開始。
4. **もう 1 回** → 停止、LED 消灯、mp4 をクローズ。
5. 次は `REC_0002.mp4`（既存番号の続きから）。1 ファイル **15 分**で `REC_0001_p2.mp4` に分割。
6. 録画中に nano が外れると自動停止する。

### 記録されるもの
- 映像 960x640（240x160 の**最近傍 4 倍**、ドットは滲まない）/ H.264 / 60fps / 既定 16Mbps
- 音声 AAC-LC 48kHz ステレオ 128kbps（nano 経由、32802Hz 由来）

### 設定（NVS、書き換えは `idf.py` 経由 or 後でボタン操作）
名前空間 `gbac`: `scale`(1〜4、既定 4) / `bitrate`(kbps、既定 16000) /
`split_min`(1〜60、既定 15) / `volume`(0〜400、既定 100)。

### ステータスログ（基板 Type-C の UART、COM5 か COM6）
10 秒ごとに受信パケット数・フレーム完結/ dropout・音声ギャップ・
エンコード枚数・拡大/エンコードの最大 ms を出す。

### HW エンコーダのベンチ（開発手順 2、最大のリスク確認）
`idf.py menuconfig` → `GBAcapture レコーダ` → `GBAC_BENCH_FRAMES` を **600** にして書き込むと、
起動時に合成映像 600 枚をエンコードして mp4 を書き、実測 fps をログに出す。
60fps を切ったら 4 倍を 3 倍（720x480）か 30fps に落とす（plan のフォールバック）。

## 8. 書き込み

1. 基板の Type-C を PC へ（CH343P → COM5 か COM6。`[System.IO.Ports.SerialPort]::GetPortNames()` で確認）。
2. **BOOT を押したまま → RST を押して離す → BOOT を離す**（ダウンロードモード）。
3. `recorder/` で環境を読み込んでビルド・書き込み:
   ```powershell
   . D:\esp\scripts\idf_env.ps1
   Set-Location C:\Users\korok\gba-capture\recorder
   cmake -G Ninja -DIDF_TARGET=esp32p4 -DPYTHON_DEPS_CHECKED=1 -B build -S .
   ninja -C build
   D:\esp\tools\python_env\idf5.5_py3.12_env\Scripts\python.exe -m esptool --chip esp32p4 -p COM5 -b 921600 write_flash @flash_args  # build/flash_args を読む
   ```
   （`idf.py` はハーネスのパイプ制限で動かない。cmake/ninja を直接使う。）
