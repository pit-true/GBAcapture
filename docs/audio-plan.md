# 音声取得プラン

## GBAの音声経路（どこから取るべきか）

```
GBA CPU ──(L/R PWM音声出力)──> RCフィルタ ──> 音量ホイール ──> アンプU6 ──> スピーカ/ヘッドホン
              ↑ここが最も「デジタルに近い」          ↑ここ以降は音量ホイールの影響を受ける
```

GBAの音声はCPU内部で全チャンネル（PSG+Direct Sound）が**デジタルミックスされ、
PWM（1bit高速スイッチング）としてCPUのL/Rピンから出力**される。つまり
**CPUの音声出力ピンの時点が実質デジタル**で、そこから先は徐々にアナログ化していく。

## 推奨タップポイント: 「SO1」「SO2」ビア（2026-07-06 スキャン拡大確認で確定）

CPU-03スキャンの拡大確認により、音声経路は次の通り:

```
CPU ──SO1/SO2(ビア)──> 音量ホイール(VOL/VR2) ──> アンプU6 ──> LOUT/ROUT(ビア) ──> P3(ジャック)/SP
        ↑プリボリューム = ここを使う                     ↑ポストアンプ = 音量0で無音になる
```

- **SO1/SO2**（U10/Q8/Q9付近、ヘッドホン検出回路の近くのビア）= CPUの音声出力そのもの。
  **音量ホイール0でもフルレベル**で信号が取れる ← 要件（GBA無音でPCに音を流す）に合致
- **LOUT/ROUT はアンプ出力**（ジャック向け・音量連動）なので**使わない**
  （当初この文書はLOUT/ROUT推奨としていたが誤り。訂正済み）
- 波形はPWMキャリア（数十〜262kHz、ゲーム側設定による）を含む
  → 高速サンプリング+デジタルフィルタで「ほぼデジタル」の取得ができる

## nanoCH32V305側の接続先

| GBA側 | nano側 | 理由 |
|---|---|---|
| **SO1** | **PA4** | ADC IN4。ヘッダに出ており未使用（上段 A4） |
| **SO2** | **PA5** | ADC IN5。同上（上段 A5） |
| (GND) | 接続済み (P1-GND) | 共通GND必須 — 映像用と共用でOK |

### RCフィルタ（2026-07-07 実装済み）

各chとも `SO線 →[1kΩ直列]→ nanoピン`、ピン側ノードから `[10nF(103)]→ G`。
fc≈15.9kHz の1次LPF。生PWM矩形波を8点程度のADCサンプルで読むと実質3-4bit相当の
量子化ノイズになるため、**アナログで滑らかにしてからADCに入れることが必須**
（市販のGBA-HDMI基板もSO1/SO2直後にRLC+オペアンプのフィルタを実装している）。
FW側のキャリア同期積分(32.768kHz×N サンプリング＋箱型平均)と組み合わせて使う。

**L/R確定（2026-07-07、firmware/gba-pantest のROMで実測）: SO1=右(R)、SO2=左(L)。**
ビューアのデコードでこの順に割り当て済み（Audio > Swap L/R は手動上書き用に残置）。

- PA4/PA5 はボード上段ヘッダの「A4」「A5」（写真 docs/photos/nanoCH32C305.jpg で確認済み）
- 直列に 1kΩ 程度を入れると安全（無くても実用上は動く見込み。GBA音声出力は
  低インピーダンス駆動、振幅は電源内 0〜VDD 範囲）

## FW側の実装方針（将来のM6）

1. TIM3等でADCを 96〜192kHz でトリガ、ADC1(PA4)/ADC2(PA5) をDMAで取り込み
   （デュアルADC同時サンプリング or 交互）
2. FWでデシメーション+ローパス（PWMキャリア除去）→ 32/48kHz PCM
3. 映像ラインパケットと同じUSBパイプに音声パケット（別マジック）を多重化
   → ビューアで WASAPI 再生。フレーム番号でリップシンク

## 参考

- GBA音声(PWM/Direct Sound)の仕様: GBATEK "GBA Sound Controller"
- SOUNDBIAS レジスタでPWM分解能/キャリアが変わる（ゲーム依存）ため、
  サンプリングは高め(≥96kHz)に取っておくのが安全
