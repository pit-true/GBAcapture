# TDD 運用ルール（t-wada 流）

このプロジェクトは t-wada（和田卓人）氏の説く TDD で開発する。

## 基本サイクル

1. **テストリスト**を書く（これから実装する振る舞いを箇条書き）
2. リストから**ひとつだけ**選び、失敗するテストを書く（**Red**）
3. テストを通す最小の実装を書く（**Green**）— 仮実装(ベタ書き)→三角測量→明白な実装
4. **Refactor** — 重複除去・意図の明確化。テストは常にグリーンを維持
5. テストリストに戻る（気づいた項目は随時リストへ追加）

## 原則

- テストは「テスト対象の振る舞い」を語る名前にする（日本語名可）
- 1テスト1アサーション目安。Arrange-Act-Assert を明確に
- Red を確認せずに実装しない（テストのテスト）
- リファクタリングはグリーンの時だけ

## 本プロジェクトでの適用範囲

| レイヤ | テスト方法 |
|---|---|
| ホスト側デコードロジック (Python) | pytest。**最優先で TDD** |
| USB パケットの組立/解析 | pytest（バイト列を純粋関数で処理する設計にする） |
| FW のビット操作・バッファ管理ロジック | 可能な限りホストでテスト可能な純粋C関数に切り出す |
| FW のペリフェラル制御 (DMA/USB) | 実機検証（M1の信号計測FW等で振る舞いを観測） |

ハードウェア依存部と純粋ロジックを分離するのが鉄則。
「テストしにくい」と感じたら設計の分離不足を疑う。

## 実行方法

```
cd host
python -m pytest -q
```

コミット前にテスト全通過を確認すること。
