# GBA LCD 映像信号仕様

GBA 本体→LCD のパラレル信号をタップして取り込む（いわゆる偽トロ方式）。
2026-07-05 に文献調査で検証済み（✅）。実機実測で最終確認したら「実測✅」に更新すること。

## タイミング（文献検証済み）

| 項目 | 値 | 検証 |
|---|---|---|
| ドットクロック (DCK) | 4.194304 MHz (= 16.777216 MHz ÷ 4) | ✅ GBATEK |
| 1ライン | 308 ドット周期（可視 240 + H-Blank 68）、~13.620 kHz | ✅ GBATEK |
| 1フレーム | 228 ライン（可視 160 + V-Blank 68） | ✅ GBATEK |
| フレームレート | 4194304 ÷ (308×228) = **59.7275 Hz** | ✅ GBATEK / SPS実測59.728Hz |

## ⚠️ 最重要: DCK はバーストクロック

**DCK は可視ピクセル区間のみ 240 パルス出る**（ブランキング中は停止）。連続 4.19 MHz ではない。
→ フリーランサンプリング不可。**DCK エッジ同期トリガ（タイマ入力キャプチャ→DMA）が必須**。
→ 逆に言えば DCK パルス数 = 有効ピクセル数なので、ラインバッファは 240 サンプルでちょうど埋まる。

## 信号詳細（squk/GBA-LCD リバエン資料より）

| 信号 | 意味 | タイミング |
|---|---|---|
| DCK (DCLK) | ピクセルクロック | **データは負エッジ（立ち下がり）で有効/ラッチ** ✅ |
| LP | ラインラッチ（水平同期相当） | 正エッジアクティブ ✅ |
| SPS | ゲートドライバスタート（垂直同期相当） | **負エッジアクティブ**。負エッジ間隔 16.743ms ✅ |
| LDR1-5 / LDG1-5 / LDB1-5 | RGB 各5bit パラレル (15bit) | ✅ |
| SPL / CLS / PS | 未配線（SPL=HSYNC系正エッジ, CLS=ゲートクロック, PS=VBLANK中デューティ変化） | 参考 |

- フレーム先頭は「SPS パルス → SPL パルス」のシーケンスでマークされる
- LDx1 が LSB か MSB かは**未確定（実キャプチャの階調で確認する）**

## データ量

- 1ピクセル 15bit → 16bit 格納で 2 byte。1ライン 480 byte、1フレーム 76,800 byte
- 転送レート ≈ 4.59 MB/s ≈ 36.7 Mbps → USB-HS バルクで十分

## 実機実測での最終確認項目（M1 マイルストーン）

1. DCK バースト数/ライン = 240、LP 数/フレーム = 228 をFWのカウンタで確認
2. DCK 負エッジでのデータ有効窓（セットアップ/ホールド）がサンプリング遅延と整合するか
3. LDx1=LSB 仮定の正否（グラデーション画面の階調で判定）
