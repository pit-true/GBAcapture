# GBA LCD 映像信号仕様

GBA 本体→LCD のパラレル信号をタップして取り込む（いわゆる偽トロ方式）。
数値は GBATEK 等に基づく設計前提値。**実測で検証したら ✅ を付けること。**

## タイミング（設計前提値）

| 項目 | 値 | 検証 |
|---|---|---|
| ドットクロック (DCK) | 4.194304 MHz (= 16.777216 MHz ÷ 4) | 未 |
| 1ライン | 308 ドット周期（有効 240 + ブランキング 68） | 未 |
| 1フレーム | 228 ライン（有効 160 + ブランキング 68） | 未 |
| フレームレート | 4194304 ÷ (308×228) = **59.7275 Hz** | 未 |
| ライン周波数 | 4194304 ÷ 308 ≈ 13.618 kHz | 未 |

## 信号

| 信号 | 意味 | 備考（要実測確認） |
|---|---|---|
| DCK | ドットクロック | どちらのエッジでデータ確定か要確認（立ち下がり想定） |
| LP | ラインパルス（水平同期） | 極性・アサートタイミング要確認 |
| SPS | フレーム開始（垂直同期） | 極性要確認 |
| LDR1-5 / LDG1-5 / LDB1-5 | RGB 各5bit パラレル | LDx1=LSB か要確認 |

## データ量の見積もり

- 1ピクセル 15bit → 16bit (RGB555) に格納して 2 byte
- 1フレーム: 240 × 160 × 2 = **76,800 byte**
- 転送レート: 76,800 × 59.7275 ≈ **4.59 MB/s ≈ 36.7 Mbps**
- USB-HS バルクの実効帯域 (~40 MB/s) に対して十分余裕あり

## 実測での検証手順（最初のマイルストーン）

ロジックアナライザがなくても CH32V305 自身で検証できる:

1. FW でタイマ入力キャプチャを使い DCK/LP/SPS の周波数を計測 → USB でPCに報告
2. LP 間の DCK カウント（=308 期待）、SPS 間の LP カウント（=228 期待）を計測
3. 結果をこのファイルに記録し「設計前提値」を「実測値」に置き換える
