# スタンドアロン録画デバイス — 確定要件と構成（2026-07-10 改訂4: Pi Zero 2 Wをフリマ調達）

## 確定した要件

| # | 項目 | 回答 |
|---|---|---|
| 1 | 記録形式 | **mp4のみ（音声入り、4x=960×640、なるべく高画質）**。生データ保存はしない |
| 2 | 使用シーン | オフ会に持ち出して録画。小型重視 |

## ボード選定

必要条件: ①USB 2.0 HSホスト（nanoから約5MB/s受ける） ②**H.264ハードウェアエンコーダが
Linuxドライバ込みで使える**（960×640@60fpsのソフトエンコードはこのクラスでは不可）
③4x拡大+受信+書込を回せるCPU/RAM ④小型 ⑤入手できること。

**調達方針（優先順）:**

1. **メルカリ/ヤフオクで中古・未使用のPi Zero 2 W（相場¥3,000〜4,500目安）** — 小型・安価・
   ソフト最楽（v4l2m2m一発+GbaCap流用）を全て満たす現実解。ヘッダ付き(WH)ならなお良い
2. Amazonマーケットプレイス新品（¥5,000台なら4ヶ月待ちより妥当。それ以上の吹っかけは見送り）
3. どちらも嫌なら **Pi 4 Model B 2GB 新品¥11,880**（確実・Type-C給電。ただし85×56mmで
   ケースがSW-150級に拡大、消費電力約2倍）
4. 急がないなら秋月の入荷（4ヶ月後）を待つ

**「Type-CじゃないPi Zero 2 Wでいいのか」について**: 本設計ではケース外面の給電口は
秋月のType-Cパネル取付キット→GPIO直配線なので、**外から見える口はType-Cになる**。
microBが残るのはケース内部のOTGデータ接続（L型アダプタ）だけ。

## 構成

```
GBA ──(既存タップ)── nanoCH32V305 ──[L型OTG+短A-Cケーブル]── Pi Zero 2 W ── microSD
（GBA本体は乾電池駆動）  (現行FW無変更)                        65×30mm      (内蔵スロット)
                                                              │ GPIO 5V/GNDピンへ給電
                    モバイルバッテリー ──[C-C or A-Cケーブル]──[ケース面のType-Cメス]
                    ボタン+LED(1穴タイプ) / RTC(DS3231ミニ、GPIO直挿し)
```

- 録画アプリ: 3EP受信→フレーム組立（GbaCap流用）→4x最近傍拡大→HWエンコーダ
  （ffmpeg `h264_v4l2m2m`）→mp4
- Wi-Fi/BTは無効化。起動20〜30秒、朝1回起動しっぱなし運用
- ルートFS read-only化+ボタン長押しシャットダウンで電源断耐性

### 記録フォーマット

| 項目 | 設定 | 理由 |
|---|---|---|
| 解像度 | **960×640（4x・最近傍拡大してからエンコード）** | H.264は色情報が2×2画素共有(4:2:0)のため、240×160のまま圧縮するとドット輪郭が滲む。4x後なら1ドット=4×4画素で滲みが実質不可視 |
| フレームレート | 59.73fps（ソースそのまま） | |
| ビットレート | 16Mbps目安（HWエンコーダなので余裕。GBA映像は実質ほぼ無劣化に見える） | 約2MB/s |
| 音声 | AAC 48kHz ステレオ（既存の32802Hz→48kHzリサンプルを流用） | |

容量: 平均10分試合=約1.2GB、1日10試合=12〜15GB → **microSD 64GBで足りる**。
録画データはexFATパーティションに置き、SDを抜いてWindowsのカードリーダーで読む。

### 時刻（Wi-Fiなし対策）

DS3231 RTCモジュール（GPIO直挿しミニ型、数百円）。最初にPC経由で合わせれば電池で数年保つ。
Pi OSは `dtoverlay=i2c-rtc,ds3231` の1行で標準対応。

### 電源

- 消費: Pi Zero 2 W録画中 約2〜2.5W + nano約0.5W = **5Vで約0.5〜0.6A**（GBA本体は含まない）
- モバイルバッテリー10000mAhで1日余裕。**低負荷自動OFF付きバッテリーは事前に連続動作確認**
- 給電経路: ケース面のType-Cメス（秋月パネル取付キット）→ 5.1kΩ×2のCC処理 →
  GPIOの5V(ピン2/4)・GND(ピン6)へ直配線。ボード側のUSBポートは給電に使わない

## ケース設計 — タカチ SW-125

**RTC・ボタン・LEDを入れても入る。** 推奨は **SW-125（外形70×40×125mm、内寸64×32×119mm、
標準価格430円税別）**。攻めればSW-100（65×35×100）にも収まる計算だが、
内部ケーブルの曲げ半径が厳しいので初号機はSW-125が無難。

```
 ┌─────────────────────────── 119 ──────────────────────────┐
 │ [Type-C取付キット]──5V/GND線──→ GPIOピン2/4(5V),6(GND)      │
 │ ┌─ Pi Zero 2 W (65×30) ─────────┐ [L型OTG]═短A-Cケーブル═╗ │ 64
 │ │  GPIO奇数列にRTCミニモジュール │                        ║ │
 │ ├─ nanoCH32V305 (~50×21) ───┐←──────────────────────────╝ │
 │ └───── GBA線19本 → グロメット穴から外へ ──────────────────┘
 └───────────────────────────────────────────────────────────┘
  高さ方向: スペーサ3mm + 基板 + ピンヘッダ+RTC ≒ 20mm < 32mm ✓
```

### パネル面の部品

| 部品 | 具体品 | 備考 |

| 外部給電口 Type-Cメス | **秋月「USB Type-Cコネクターパネル取付キット」AE-USB2.0-TYPE-C-PNL（¥250）** | L型金具でネジ止め。5V/GNDをGPIOへ直配線 |

## 開発ステップ

1. 部品購入（上表）
2. セットアップ: Raspberry Pi OS Lite (64bit)。初期設定・パッケージ導入時のみネット接続
   （家でUSBガジェットモード+PC接続共有等）。`ffmpeg -c:v h264_v4l2m2m` で
   テストパターン960×640@60のHWエンコードが通ることを先に確認
3. **疎通確認**: GbaCap.Cliをlinux-arm64ビルドし、Pi上で `freq` / `capture` が通ることを確認
   （プロトコル層流用の証明。既存コード無変更）
4. 録画アプリ（TDD、ロジックはまずPC上でテスト）: 3EP受信→フレーム組立→4x最近傍拡大→
   エンコーダパイプ（16Mbps + AAC）→試合単位のmp4分割
5. GPIOボタン/LED/RTC（I2Cオーバーレイ）、systemd自動起動、read-only化、exFATパーティション
6. モバイルバッテリーで実測（連続録画・自動OFFしないか・発熱）
7. ケース加工・組み込み
