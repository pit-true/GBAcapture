# スタンドアロン録画デバイス — 確定要件と構成（2026-07-10 改訂3: ボード再選定）

## 確定した要件

| # | 項目 | 回答 |
|---|---|---|
| 1 | 記録形式 | **mp4のみ（音声入り、4x=960×640、なるべく高画質）**。生データ保存はしない |
| 2 | 使用シーン | オフ会に持ち出して録画。小型重視 |
| 3 | 録画量 | ポケモン対戦を1日10試合程度。1試合最大30分、平均10分 |
| 4 | 電源 | **モバイルバッテリーからUSB Type-Cで給電**（ケース外面にType-Cメス）。LiPo基板の再現・拡張は将来の基板化フェーズで |

| 7 | プレビュー | LEDのみ |

| 10 | PC取り込み | SDカードをカードリーダーで読む（録画領域はexFAT） |

## ボード選定

必要条件: ①USB 2.0 HSホスト（nanoから約5MB/s受ける） ②**H.264ハードウェアエンコーダが
Linuxドライバ込みで使える**（960×640@60fpsのソフトエンコードはこのクラスでは不可）
③4x拡大+受信+書込を回せるCPU/RAM ④小型 ⑤入手できること。

### 再選定（2026-07-10）: **Radxa Zero 3W** に変更

当初案のRaspberry Pi Zero 2 Wが**秋月で売り切れ・次回入荷4ヶ月後**、かつコネクタが
microUSBで旧規格のため、**同一フォームファクタ（65×30mm）でUSBが全部Type-Cの
Radxa Zero 3W（Rockchip RK3566）**に変更する。

| 項目 | Radxa Zero 3W |
|---|---|
| SoC / RAM | RK3566（4×Cortex-A55 1.6GHz）/ 1〜8GB LPDDR4（**2GB版を選ぶ**） |
| HWエンコーダ | **H.264/H.265 最大1080p60** → 960×640@59.73は余裕 |
| USB | **USB 2.0 OTG Type-C（給電兼用）+ USB 3.0 HOST Type-C** — nanoへは**C-Cケーブル直結**でき、旧microB用のL型OTGアダプタが不要になる |
| ソフト | Radxa公式Debian。エンコーダはRockchip MPP経由（GStreamerの`mpph264enc`、またはffmpeg-rockchipの`h264_rkmpp`）。**Piの`v4l2m2m`ほど「無設定で一発」ではないが、定番SoCなので手順は確立済み** |
| .NET 8 | ARM64対応 → GbaCapライブラリ流用可（2GBで余裕） |
| Wi-Fi/BT | 搭載だが**本機は使わない運用**なので無効化（電波を出さなければ技適の問題も生じない） |
| 入手 | **Amazon.co.jpに複数出品（2GB・ヘッダ実装済み版で3千〜5千円程度）**。「with GPIO (40 Pin Header)」版を選ぶとRTC直挿しが楽 |
| 注意 | RK3566はPi Zero 2Wよりやや発熱する → **小型ヒートシンク推奨**（SW-125内に通気穴） |

## 構成

```
GBA ──(既存タップ)── nanoCH32V305 ──USB C-Cケーブル── Radxa Zero 3W(USB3 HOSTポート) ── microSD
（GBA本体は乾電池駆動）  (現行FW無変更)                      65×30mm
                                                            │ GPIO 5V/GNDピンへ給電
                    モバイルバッテリー ──[C-C or A-Cケーブル]──[ケース面のType-Cメス]
                    ボタン+LED(1穴タイプ) / RTC(DS3231ミニ、GPIO直挿し)
```

- 録画アプリ: 3EP受信→フレーム組立（GbaCap流用）→4x最近傍拡大→MPPエンコーダへ→mp4
- Wi-Fi/BTは無効化。起動20〜30秒、朝1回起動しっぱなし運用
- ルートFS read-only化+ボタン長押しシャットダウンで電源断耐性

### 記録フォーマット

| 項目 | 設定 | 理由 |
|---|---|---|
| 解像度 | **960×640（4x・最近傍拡大してからエンコード）** | H.264は色情報が2×2画素共有(4:2:0)のため、240×160のまま圧縮するとドット輪郭が滲む。4x後なら1ドット=4×4画素で滲みが実質不可視 |
| フレームレート | 59.73fps（ソースそのまま） | |
| ビットレート | 16Mbps目安（HWエンコーダなので余裕。GBA映像は実質ほぼ無劣化に見える） | 約2MB/s |
| 音声 | AAC 48kHz ステレオ（既存の32802Hz→48kHzリサンプルを流用） | |

容量: 平均10分試合=約1.2GB、1日10試合=12〜15GB → **microSD 64GBで足りる**。
録画データはexFATパーティションに置き、SDを抜いてWindowsのカードリーダーで読む。

### 時刻（Wi-Fiなし対策）

DS3231 RTCモジュール（GPIO直挿しミニ型、数百円）。最初にPC経由で合わせれば電池で数年保つ。
※Radxa Zero 3のGPIOはPi互換40ピン。I2Cピン(3/5)の有効化はデバイスツリーオーバーレイ設定が要る（セットアップ時に実施）

### 電源

- 消費: Radxa Zero 3W録画中 約2〜3W + nano約0.5W = **5Vで約0.6A**（GBA本体は含まない）
- モバイルバッテリー10000mAhで1日余裕。**低負荷自動OFF付きバッテリーは事前に連続動作確認**
- 給電経路: ケース面のType-Cメス（秋月パネル取付キット）→ 5.1kΩ×2のCC処理 →
  GPIOの5V(ピン2/4)・GND(ピン6)へ直配線。ボード側のUSBポートは給電に使わない

## ケース設計 — タカチ SW-125

**RTC・ボタン・LEDを入れても入る。** 推奨は **SW-125（外形70×40×125mm、内寸64×32×119mm、
標準価格430円税別）**。Radxa Zero 3WはPi Zero 2Wと同寸(65×30)なのでレイアウトは変わらず、
むしろL型OTGアダプタが消えて配線が短くなる。

```
 ┌─────────────────────────── 119 ──────────────────────────┐
 │ [Type-C取付キット]──5V/GND線──→ GPIOピン2/4(5V),6(GND)      │
 │ ┌─ Radxa Zero 3W (65×30) ───────┐═C-C短ケーブル═╗          │ 64
 │ │  GPIO奇数列にRTCミニモジュール │                ║          │
 │ ├─ nanoCH32V305 (~50×21) ───┐←──────────────────╝          │
 │ └───── GBA線19本 → グロメット穴から外へ ──────────────────┘
 └───────────────────────────────────────────────────────────┘
  高さ方向: スペーサ3mm + 基板 + ピンヘッダ+RTC ≒ 20mm < 32mm ✓（ヒートシンクも収まる）
```

### パネル面の部品

| 部品 | 具体品 | 備考 |

| 外部給電口 Type-Cメス | **秋月「USB Type-Cコネクターパネル取付キット」AE-USB2.0-TYPE-C-PNL（¥250）** | L型金具でネジ止め。5V/GNDをGPIOへ直配線 |

## 開発ステップ

1. 部品購入（上表）
2. セットアップ: Radxa公式Debian。初期設定・パッケージ導入時のみネット接続
   （家でUSB経由のPC接続共有等）。GStreamer+MPP（`mpph264enc`）または
   ffmpeg-rockchipでHWエンコードの動作確認（テストパターンで960×640@60が出ることを先に確認）
3. **疎通確認**: GbaCap.Cliをlinux-arm64ビルドし、Radxa上で `freq` / `capture` が通ることを確認
   （プロトコル層流用の証明。既存コード無変更）
4. 録画アプリ（TDD、ロジックはまずPC上でテスト）: 3EP受信→フレーム組立→4x最近傍拡大→
   エンコーダパイプ（16Mbps + AAC）→試合単位のmp4分割
5. GPIOボタン/LED/RTC（I2Cオーバーレイ）、systemd自動起動、read-only化、exFATパーティション
6. モバイルバッテリーで実測（連続録画・自動OFFしないか・発熱）
7. ケース加工・組み込み
